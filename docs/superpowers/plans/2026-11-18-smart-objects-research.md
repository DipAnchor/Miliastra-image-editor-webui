# 可编辑打包对象调研与规划

> 状态：按阶段实施中；普通 JSON 保存兼容与前端纯逻辑原型已验证，对象 JSON 校验已接入；完整 UI/导出尚未完成。日期：2026-11-18。本文不是全部实现或实机验证的证明。

## 1. 已确认范围

用户选择“可进入编辑的打包对象”，不是一次性多选，也不是共享源实例系统。
- 外部作为一个图层：移动、Z 旋转、正向等比缩放。
- 内部保留图层、组、文字、素材与原始几何，可进入编辑。
- 内部使用独立草稿；Ctrl+S 应用到对象并留在编辑态，每次有变化的保存记一次主撤销；完成仅提交保存后的新改动并退出；放弃仅丢弃最近一次保存后的未应用修改。
- 用户已确认画框在有变化的保存／完成时自动适配，编辑中不实时调整；无变化不适配、不提交，空内容保留上次画框，不增加手动尺寸入口。
- 可以解除为普通组，保持当前父级归属与内部组织；具体规则见下文。
- 按阶段实现与验证；不提交、不推送，除非用户另外明确要求。
第一版不含：外链源、共享源/实例联动、替换源、滤镜、透视/自由变形、非等比/负向缩放、栅格化、PSD/PSB 兼容。含 X/Y 倾转的内部内容暂不自动禁用对象整体变换；其矩阵组合和导出能力必须通过测试与诊断验证，不能静默清零或宣称已获真机证明。嵌套智能对象暂不开放为首版创建入口，列入待做清单。
“临时”指可解除，不是刷新后丢弃；对象必须随项目保存。

## 2. 参考与区别

Adobe 官方说明支持把一个或多个图层转换为一个嵌入式智能对象，双击缩略图编辑内容，保存后更新实例：
https://helpx.adobe.com/photoshop/using/create-smart-objects.html （访问日期 2026-11-18，页面标注更新日期 2026-02-23）。
本项目借鉴“内容与外部变换分离”，不承诺完整 Photoshop 智能对象行为；尤其第一版复制是独立副本，而不是共享内容实例。

普通组解决组织与继承；多选解决一次批量操作；打包对象解决长期保留的独立坐标系和外部单一选择边界。不要仅给 SceneGroup 加一个 folded 标记，也不要把内容先转成 PNG：后者破坏文字/素材编辑，并且不能直接当作已有千星素材 id 导出。

## 4. 推荐模型：嵌入子场景 + 对象壳

建议增加显式 smart-object 元素分支；不要把假 rectangle 同时当对象使用。将共享模型从 App 类型区抽到 sceneModel.ts（仅相关类型迁移，不重构全 App）。

对象壳保存：id、图层名、可见/锁定、父 groupId、zIndex，以及中心 position、Z rotation、单一正数 scale。壳的 width/height 为内部当前 frame × scale 的派生值，不再拥有一对独立可变宽高；frame 在编辑中稳定，在有变化的保存／完成时适配。

对象 content 保存：局部 elements、groups、当前 frame 的 width/height；递归对象包含在局部 elements 中。不要嵌入整份 SceneDocument.library/meta，否则会复制全局收藏并造成无关递归膨胀。素材引用仍使用原 imageAssetId/prefabId 等字段。

建议未来代码模块边界（以下文件为拟新增，不代表已存在）：
- frontend/src/sceneModel.ts：判别联合、SceneContent、对象变换契约。
- frontend/src/smartObjects.ts：打包/解除/深复制/规范化，纯逻辑。
- frontend/src/sceneTraversal.ts：递归访问、素材/能力扫描、作用域寻址。
- frontend/src/sceneFlatten.ts：局部到世界几何展开、导出诊断。
- frontend/src/SmartObjectEditor.tsx：草稿编辑壳、面包屑、完成/取消。
- backend/app/smart_objects.py：递归校验、几何展开和诊断；后端为直接 API 请求保留同等校验，不能只信任 UI。

第一版无需全局 source 定义表和 reference id；深复制后内容独立。内部 id 采用作用域路径寻址，复制/追加递归重映射本地元素 id、组 id 与 groupId/parentId；不可只替换对象壳 id。

## 5. 交互规格建议（未确认项不可当作最终授权）

### 打包
- 右键“转换为智能对象”；对象行使用专属图标。选中普通组时包含其完整后代；同时选中祖先/后代先去重。
- 单个普通组可以直接转换为智能对象，内部完整保留该组内容；转换后外层对象替代该组在父级中的位置。
- 不连续图层不直接转换：先提供“先编组再转换为智能对象”的明确操作路径；编组后对象仍属于原父级。转换失败时不能自动重排或部分打包。
- 隐藏/锁定子层必须保留，不能用“当前可选图元”过滤掉。推荐锁定目标不允许由画布入口打包，先显式解锁；组内隐藏层仍随组进入。
- 初始 frame 根据全部所含叶的几何边界（包括隐藏／锁定内容）计算，转换成局部坐标，外部壳初始 scale=1、Z=0。边界是几何边界，不承诺含文字字形溢出或羽化的像素包围盒。
- 打包一次撤销；打包前后可见画面应一致。

### 外部操作
- 主画布命中内部任意可见内容时选中对象壳，不直接选内部图层；空洞与外框命中策略需交互测试。
- 只有对象一套手柄；整体只支持正向等比缩放，不受全局“自由缩放”覆盖。frame 与派生宽高只读，不提供手动画框尺寸入口。
- 对象自身锁定/隐藏作用于整体；复制得到独立内部内容；删除壳连同内容一次撤销。
- 外层与普通图元混选时，移动/Z 旋转/等比缩放按同一世界坐标运算，禁止批量自由缩放旁路限制。

### 内部编辑
- 双击对象缩略图或菜单“编辑内容”进入独立编辑作用域，显示“主场景 > 对象名”的面包屑及完成/取消。
- 使用未受外部缩放/旋转的局部坐标。仅内部图层显示于图层面板；先复用已有编辑能力，不另造第二套图元逻辑。
- 草稿有自己的撤销/重做；保存有变化时回写当前对象一次主提交并更新保存基线；完成仅提交之后的新改动后退出；放弃不撤销已保存的主历史。
- 已确认保存时自动适配，非实时：编辑中 frame 稳定，新增内容允许溢出，画布不隐式 clip。有变化的 Ctrl+S／完成按全部叶（含隐藏／锁定）的 `selectionBounds` 几何 AABB 计算新 frame，宽高各至少 1；空内容保留上次 frame，无变化不适配。局部平移 `newFrame/2 - boundsCenter`，壳 position 补偿 `scale * Rscreen(Z) * (boundsCenter - oldFrame/2)`，保持编辑后内容在主场景中的视觉位置，rotation/scale 不变，但对象中心与外框可变。
- 每次适配将 draft/saved/past/future 与内部编辑器历史以同一局部偏移重基，保留撤销／重做；不把适配拆成额外主撤销，不改变导出协议。
- 编辑中打开其它存档、导入覆盖、新建或关闭编辑作用域必须提示“应用/放弃/继续编辑”。导出前处理未应用草稿。内部 Ctrl+S/保存只应用当前对象并留在编辑态，不触发整份作品收藏/存档；无变化不新增主撤销，完成只提交保存后的新变化。
- 内部编辑只作用于当前草稿，不影响外部选择、图层、变换或主历史；只有明确保存/完成才回写。嵌套智能对象暂不开放，列入待做清单。

### 解除
- 解除后变成普通组，保留当前父级归属并将子层几何映射到父坐标系，保持当前外观；不是退回打包前的位置。唯一完整根组直接复用其 ID、保留真实子组，不额外增加层级；外壳名称／父级／层序合并到该组，透明度相乘、显隐取交集、锁定取并集。只有多根组、散落图元或无组内容才新建收拢组。
- 撤销解除后恢复对象内容及壳变换，不能从展平结果逆推源数据。
- 无法精确展开时阻止解除并列出具体后代和原因；不得静默近似或丢内容。

## 6. 变换与视觉兼容风险

对局部中心 c 使用 world = position + scale * Rscreen(Z) * (c - frameCenter)。Z 使用当前 rotationMatrix 的符号约定。对子元素的投影线性矩阵应左乘外层变换，再验证能否在当前元素模型中表示；不能只改中心就宣布刚体正确。

纯 2D 子层在正向等比缩放和 Z 旋转下可展开为尺寸等比变化与旋转组合；测试必须比较每个角点，而不仅中心。

内部已有 X/Y 倾转时，外层 Z 复合不能直接沿用 orig.rotation - deg 的简式。按用户决定，暂不因这类内容禁用对象变换；保留源倾转数据，以矩阵组合、特征测试和具体诊断验证，不清零，不把未验证行为宣传为真机事实。

等比缩放仍需审查文字字号/scale、原生布局锚点、九宫格图片边框、Lua 蒙版尺寸/羽化等：这些不能只改 width/height 就承诺视觉等比。暂不预设按内容类型禁用变换的策略；实施中发现确实无法表达的情况应报告具体证据并重新确认，而非自行恢复禁用规则。已有导出限制继续适用。

透明度沿用现有逐层烘焙近似：不新增“先整体合成再乘 alpha”的承诺。UI 应沿用同一近似，不让嵌套 DOM opacity 意外变成另一种语义。精确合成是独立项目，不夹带到第一版。

## 7. 保存/导出契约

| 载体 | 要求 |
|---|---|
| JSON | 保留完整内容与壳、隐藏/锁定/组、版本字段；后端递归校验，不降级未知对象为 rectangle |
| 本地历史/存档/启动恢复 | 完整根场景；草稿不伪装成已应用内容；配额失败明确提示，不悄悄吞错 |
| 收藏/复制/追加 | 深复制自包含内容，递归 id 重映射；新对象之间不共享可变引用 |
| Lua | 运行数据按既有格式展开；编辑结构放注释快照。快照包含原始对象，drawingHash 对应实际展开的绘图行。外部绘图改动触发原有失效规则并提示结构无法还原 |
| GIA/容器 GIA | 用能力检查后的叶子元素展开；不发明新数据列，不生成 UIControlGroup 包装层，不把对象强行当新素材 id |
| PNG/CSS/SVG | 和统一几何展开策略一致；原有元件/蒙版/圆环等格式限制继续适用，不以对象壳隐藏内部限制 |
| WebMCP | 递归读取、对象操作、作用域选择、预览和导出遵循同一契约；不能让旧平面接口误改/删除不在当前作用域的 id |

前后端展开实现使用同一组固定 JSON 测试向量验证，避免预览、网页导出、直接 API 请求产生三种结果。叶子遍历必须用于素材预加载、luaOnly 检测、模板索引收集和警告，不只是用于绘制。

## 8. 分阶段实施建议

每阶段先加失败测试再实现；本规划不自动授权提交。每个阶段都可单独评审，不直接一次铺开。

### A. 契约与保存先行
- 锁定已确认的组转换、不连续图层先编组、内部隔离、普通组解除、保存智能对象规则；嵌套列入待做清单。
- 为现有 JSON groups/locked/schemaVersion 的往返补测试；修复相关导入/模型白名单缺口，作为对象持久化前置，不顺带重写其它导入格式。
- 新递归类型、规范化、版本、错误诊断；覆盖旧文件默认值、坏引用、深度和节点预算。
- 验收：JSON、收藏、存档、Lua 快照能保留未变换对象；非法内容明确失败，不静默变成矩形。

### B. 纯逻辑：打包/展开/解除
- 实现局部坐标、保存时适配边界、组内连续层序检查、深复制/重映射、作用域寻址；不连续选择先编组再转对象。
- 实现基础变换与能力检查，保护混合轴、文字、拉伸图等不能确认的情况。
- 验收：打包前后、变换后解除，角点/层序一致；隐藏/锁定与嵌套不丢；源数据在多次变换后不变。

### C. 交互闭环
- 独立组件承载草稿/面包屑/完成取消，App 仅接线；保持普通组现有操作不变。
- 对象图层行、单一命中、手柄限制、复制删除、键盘与右键入口。
- 验收：取消零影响，完成一次主撤销；内层历史不串到外层；新建/导入/打开存档不绕过草稿保护。

### D. 全链路兼容与收尾
- 递归能力扫描、全部导出、Lua 快照双轨、WebMCP、收藏与追加导入。
- 中英文文案、用户指南和技术设计更新。
- 验收：自动测试与实际页面拖拽/双击/完成取消通过；GIA/Lua 真机结果未验证前明确标注。

## 9. 验证清单

新增测试建议：frontend/tests/smartObjects.test.mjs、sceneFlatten.test.mjs、SmartObjectEditor.test.tsx；backend/tests/test_smart_objects.py，并扩已有 test_lua_scene.py 和 JSON/库测试。测试加载方式沿用现有 node 纯逻辑和 vitest UI 项目惯例。

核心回归：
1. 旋转矩形+椭圆+隐藏文字打包，所有字段/四角保留；解除并撤销可恢复。
2. 外层 Z 在 -135/-40/40/90/179 度、比例 0.25/1/3 下比较全部叶子四角。
3. 缩小再放大不改内部源数据；重复复制/追加无 id 冲突或共享引用。

6. JSON 导入导出、Lua 快照不变/绘图已改、收藏、存档恢复、WebMCP/HTTP 导出都覆盖对象内部。
7. 通过实际拖拽检查整体旋转，不以 MCP 直接写角度代替；像素比对固定实测中心/角度，不搜索最优对齐。
